# Антипаттерны AI-слоя

Формат: **симптом → почему больно → как чинить**. Все пункты — из реальных разборов, а не
из общих соображений.

---

### 1. Физический model ID в бизнес-коде

**Симптом.** `model: 'gpt-4o-mini'` в сервисе; слаг провайдера в `if`; таблица `ai_models`
хранит `openrouter/google/gemini-3.7-flash`.

**Почему больно.** Смена модели становится релизом кода или миграцией БД. Через полгода
модель депрекейтят, и правки расползаются по десяткам файлов. Тенант не может иметь свою
модель без ветвления в коде.

**Чинить.** Логические алиасы по ролям (`default`/`fast`/`fallback`/`batch`). Физический ID
живёт только в конфиге шлюза и в журнале как постфактум-наблюдаемость. Реестр моделей
физические ID **намеренно не хранит**.

---

### 2. Прямой вызов SDK «только для эмбеддингов»

**Симптом.** Весь контур через шлюз, но `new OpenAI()` в модуле индексации.

**Почему больно.** Второй путь к провайдеру = второй набор ключей, отсутствие учёта
стоимости, невидимость в журнале, и провайдер, который нельзя сменить конфигом.

**Чинить.** Добавить модель эмбеддингов в конфиг шлюза. Если её там нет — это блокер
для RAG, а не повод обойти правило.

---

### 3. Фреймворк агента протёк в домен

**Симптом.** `import { Agent } from '@mastra/core'` в доменном сервисе; код, разбирающий
`res.steps[i].toolCalls[j].payload`.

**Почему больно.** Фреймворки агентов меняют API чаще всех остальных зависимостей.
Обновление минорной версии ломает бизнес-модули.

**Чинить.** Фасад рантайма: домен передаёт `ToolDescriptor` и zod-схему, получает
`{ object, usage, physicalModel, toolCalls }`. Всё специфичное — внутри одного файла.

---

### 4. Агент с прямым доступом к БД

**Симптом.** Инструмент агента вызывает Prisma/ORM напрямую «для скорости».

**Почему больно.** Модель, поведение которой зависит от внешнего текста, получает прямой
доступ к данным без политики, аудита и проекции. Это дыра в авторизации и приватности,
которую не видно на ревью — код выглядит обычным.

**Чинить.** Governed-путь: tool-эндпоинт → политика (fail-closed) → владелец данных →
safe-проекция. См. `tool-contracts.md`.

---

### 5. Промпт в коде

**Симптом.** Многострочный шаблонный литерал в сервисе; правка промпта = деплой.

**Почему больно.** Регресс качества невозможно связать с изменением; нельзя откатить
только промпт; нельзя дать тенанту свою формулировку; A/B невозможен.

**Чинить.** Реестр промптов с иммутабельными версиями, одна активная на (tenant, key),
`promptVersion` — в каждой записи журнала.

---

### 6. Алиас в поле «модель» журнала

**Симптом.** В `ai_task_executions.model` пишется `task-fast`, `provider` пустой.

**Почему больно.** После срабатывания fallback невозможно узнать, кто реально ответил.
Смену провайдера нечем доказать, стоимость не отнести к upstream, регресс качества не
привязать к модели. Пробел обнаруживается ровно тогда, когда нужен разбор инцидента.

**Чинить.** Перехват заголовков шлюза (`x-…-model-name`, `x-…-response-cost`) в кастомном
`fetch`; `model` = физическая, `modelAlias` = логический — **оба** поля.

---

### 7. Телеметрия в переменной модуля

**Симптом.** `let lastModel: string` на уровне модуля, заполняется в интерцепторе.

**Почему больно.** Вызовы идут параллельно — модель и стоимость одного запроса
приписываются другому. Журнал врёт тихо, под нагрузкой всегда.

**Чинить.** `AsyncLocalStorage` (или аналог контекста запроса): каждый вызов выполняется в
своём слоте телеметрии.

---

### 8. Модель принимает необратимое решение

**Симптом.** LLM возвращает `websiteStatus: 'verified'` / `shouldSend: true`, и это
записывается как есть.

**Почему больно.** Решение невозможно объяснить, оспорить и воспроизвести; галлюцинация
становится состоянием системы; аудит показывает «так решил ИИ».

**Чинить.** Модель отдаёт **суждение + `reasons[]` + `confidence`**; итог считает
детерминированный код, где вклад модели — отдельная ось с потолком и порогом. Асимметрия
допустима и часто нужна: «принадлежит» повышает уверенность, «не принадлежит» не понижает.

---

### 9. Одна строгая схема выхода

**Симптом.** `z.object({ channel: z.enum([...]), ... })` подаётся модели как контракт, и
любое отклонение роняет задачу с `no object generated`.

**Почему больно.** Задача проваливается целиком из-за `"e-mail"` вместо `"email"`.
Стоимость потрачена, результат потерян.

**Чинить.** Две схемы: толерантная `LlmXSchema` для модели + строгий `XOutput` после
`normalizeX()`. Enum'ы нормализовать в коде, с детерминированным дефолтом и логированием
факта нормализации.

---

### 10. Смешение tool-loop и детерминированного сбора

**Симптом.** `gatherContext()` собрал данные, и те же инструменты переданы агенту.

**Почему больно.** Модель повторно зовёт инструмент, данные которого уже во входе:
лишние шаги, лишние деньги, риск упереться в `maxSteps` и не финализировать ответ.

**Чинить.** Если контекст собран детерминированно — вызывать агента **без** tools.

---

### 11. Идемпотентность без сохранённого результата

**Симптом.** Есть `idempotencyKey` и запись выполнения, но результат не хранится.

**Почему больно.** Повтор «узнаёт» ключ, но отдать нечего — либо возвращается пустота,
либо задача пересчитывается за деньги. Оркестратор при replay получает разные ответы.

**Чинить.** Хранить финальный результат рядом с записью выполнения; возвращать
`reused: true`, чтобы вызывающий отличал повтор.

---

### 12. Бюджет проверяется до идемпотентности

**Симптом.** Гейт бюджета — первым шагом runner'а.

**Почему больно.** Исчерпанный лимит начинает отклонять повторы уже завершённых и
оплаченных задач: клиент не может забрать собственный результат.

**Чинить.** Порядок: idempotency → бюджет → всё остальное.

---

### 13. Fallback внутри одной provider-семьи

**Симптом.** `default: gpt-4o` → `fallback: gpt-4o-mini`.

**Почему больно.** Сбой или rate-limit вендора кладёт всю цепочку одновременно — fallback
не срабатывает именно тогда, когда нужен.

**Чинить.** Каскад по **разным** семьям. И проверить, что резервная модель действительно
поддерживает нужные возможности (некоторые модели с tools не дают строгий structured
output — такая годится как последний резерв для текста, но не для JSON-задач).

---

### 14. Free-tier модель как основной маршрут

**Симптом.** `default` указывает на бесплатную модель общего пула.

**Почему больно.** Регулярные upstream-429 из общего пула: лишний retry → fallback →
латентность на **каждом** запросе. Экономия оборачивается нестабильностью и ростом
стоимости за счёт повторов.

**Чинить.** Дешёвая, но выделенная модель для `default`; бесплатные — только в резерве
или для offline-прогонов.

---

### 15. Второй эндпоинт вместо второго транспорта

**Симптом.** У задачи появился «внутренний» эндпоинт для оркестратора со своей копией
логики.

**Почему больно.** Два пути расходятся: guardrails, идемпотентность, журнал чинятся в
одном и остаются сломанными в другом.

**Чинить.** Второй вход — это **другой транспорт к той же задаче**: тонкий контроллер с
другой аутентификацией, вызывающий тот же use case.

---

### 16. Запреты в промпте

**Симптом.** «Никогда не упоминай цены» — только в тексте системного промпта.

**Почему больно.** Промпт — вероятностная просьба, а не гарантия; инъекция или редкая
формулировка её обходит. Проверить, что запрет действует, нечем.

**Чинить.** Жёсткие запреты — детерминированной политикой на выходе (см.
`ai-evals-ops/references/guardrails.md`). Промпт — для формы, политика — для запретов.

---

### 17. Логика фасада

**Симптом.** `ExecuteTask` начал сам обогащать вход, ретраить, писать в БД.

**Почему больно.** Фасад превращается во второй runner, который никто не тестирует.

**Чинить.** Фасад: валидация типа/версии → разбор `input` → вызов use case. Всё.
