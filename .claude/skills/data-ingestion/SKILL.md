# Конвейер сбора и обогащения данных

Главный принцип: **сырые данные из внешнего мира недостоверны по умолчанию.** Задача
конвейера — не «загрузить», а превратить противоречивый ввод в факты с известной
уверенностью и прослеживаемым происхождением.

## Когда применять

- Подключение источника данных (API, каталог, карта, поиск, скрейпинг).
- Дубликаты, склейка записей, «одна компания четырьмя строчками».
- Проверка фактов: тот ли это сайт, живой ли телефон, работает ли компания.
- Скоринг и приоритизация собранного.
- Бюджеты и лимиты внешних API.

## Когда НЕ применять

- Отправка сообщений собранным контактам → `outbound-messaging`.
- Устройство AI-слоя, промпты, tools → `ai-layer-architecture`.
- Границы сервисов, durable-оркестрация → `platform-architecture`.

## Инварианты

1. **Каждый провайдер — за единым контрактом адаптера.** Слаг вендора в бизнес-коде
   запрещён; добавление источника = адаптер + запись в реестре, без правок конвейера.
2. **Реестр источников и транспорт — разные слои.** Реестр отвечает за экономику
   (приоритет, лимиты, бюджет, health, платность), шлюз — за authz, аудит и маршрутизацию,
   адаптер — за конкретный API.
3. **Сырой ответ сохраняется отдельно от нормализованного.** Без сырья невозможно
   переразобрать данные после исправления парсера.
4. **Идентичность вычисляется детерминированно.** Ключи склейки — каскад правил, а не
   «похоже же».
5. **Факт без свидетельства — не факт.** Любое утверждение о сущности хранит источник,
   время и способ получения.
6. **Правила решают, модель добирает.** LLM вызывается, когда детерминированных признаков
   не хватило, и отдаёт суждение + причины, а не итоговый статус.
7. **Единичное наблюдение не даёт вывода.** Для «сайт мёртв», «телефон не отвечает» нужна
   серия попыток с интервалом.
8. **Каждый шаг идемпотентен.** Повторный прогон не создаёт дублей и не тратит бюджет
   заново.
9. **Синтетика помечена.** Тестовые данные отличимы от реальных на уровне поля, а не
   комментария.

## Порядок построения

1. **Определить единицу данных и её идентичность** — что считается одной сущностью и по
   каким признакам две записи — это одна. До этого не писать ни строчки адаптера.
2. **Описать контракт адаптера** для класса источников. → `references/source-registry.md`
3. **Завести реестр источников**: приоритет, возможности, платность, лимиты, health.
4. **Построить конвейер по этапам**, каждый с собственной идемпотентностью.
   → `references/pipeline.md`
5. **Дедуп и склейка** — каскад блокинга, пороги, очередь ручного разбора.
   → `references/dedup-and-identity.md`
6. **Верификация фактов** — свидетельства, детерминированные правила, вклад модели с
   потолком. → `references/verification-and-confidence.md`
7. **Скоринг** — объяснимый, из зафиксированных признаков.
8. **Приёмка** — живой прогон на реальном источнике с числами до/после.

## Правила assets

- `assets/source-adapter.ts` — контракт адаптера источника с `capabilities()` и
  классификацией ошибок провайдера. Копировать при подключении первого источника.
- `assets/dedup.ts` — чистые функции: триграммное сходство, каскад блокинга, классификация
  пары. Работают без БД, поэтому тестируются напрямую.
- `assets/confidence.ts` — сложение вкладов признаков с потолками и порогами.

## Профиль текущего стека (LeadMap)

Источники (Geoapify, Overpass, Brave) обёрнуты в **MCP-серверы** и вызываются через **MCP
Gateway** с OPA-PEP (fail-closed) и аудитом. `SourceManager` выбирает источник по
приоритету/бюджету и зовёт шлюз; governance — не его дело. Оркестрация многошаговых
цепочек — **Temporal** (`collector-service/src/temporal/`). AI-задачи (матчинг сайта,
классификация ссылки) — через `ai-service` по фасаду `ExecuteTask`.

Замены компонентов — `platform-architecture/references/stack-selection.md`.

## Чеклист

- [ ] Второй источник того же класса подключается без правок конвейера.
- [ ] Сырые ответы сохраняются и позволяют переразбор.
- [ ] Ключ идентичности детерминирован и покрыт тестами на реальных парах.
- [ ] Дедуп имеет зону неопределённости → ручной разбор, а не «решим порогом».
- [ ] У каждого факта есть свидетельство: источник, время, способ.
- [ ] Модель не выставляет статус — только суждение с причинами.
- [ ] Повторный прогон не создаёт дублей и не тратит бюджет.
- [ ] Бюджет и rate-limit источника проверяются **до** вызова.
- [ ] Живой прогон падает, если выборка пуста.
