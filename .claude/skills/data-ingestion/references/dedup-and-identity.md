# Идентичность и дедупликация

Вопрос «две записи — это одна сущность?» решается **каскадом детерминированных правил**, а
не единой формулой похожести. Формула даёт число, которое невозможно объяснить и
невозможно отладить.

## Каскад блокинга

Правила упорядочены по убыванию надёжности. Первое сработавшее — решение.

| # | Признак | Надёжность | Оговорка |
|---|---|---|---|
| 1 | совпал нормализованный **телефон** | высокая | сетевые компании и колл-центры делят номер |
| 2 | совпал **домен** | высокая | конструкторы сайтов и агрегаторы дают общий домен |
| 3 | **гео + название** (радиус + сходство ≥ порога) | средняя | сети в одном ТЦ |
| 4 | **адрес + название** | средняя | БЦ с сотней арендаторов |

Оговорки — не теория: именно они дают ложные склейки. Против них — списки исключений
(общие домены конструкторов, номера агрегаторов), которые пополняются из разбора инцидентов.

## Нечёткое сходство названий

Триграммы (тот же принцип, что `pg_trgm` в PostgreSQL) — предсказуемо, объяснимо, работает
и в БД, и в памяти:

```ts
export function trigrams(s: string): Set<string> {
  const t = `  ${s.trim().toLowerCase()} `;
  const set = new Set<string>();
  for (let i = 0; i < t.length - 2; i++) set.add(t.slice(i, i + 3));
  return set;
}

/** Jaccard по триграммам — аналог similarity() в [0..1]. */
export function trigramSimilarity(a: string, b: string): number {
  const ta = trigrams(a), tb = trigrams(b);
  let inter = 0;
  for (const g of ta) if (tb.has(g)) inter++;
  const union = ta.size + tb.size - inter;
  return union === 0 ? 0 : inter / union;
}
```

Важно: **функции чистые** — их можно прогнать на реальных парах названий без БД. Поиск
кандидатов в базе делает индекс (`GIN` + `pg_trgm`), логика классификации — эти функции.
Так одна и та же логика работает в запросе и в тестах.

Перед сравнением названия нормализуются одинаково: правовые формы (`ООО`, `ИП`, `LLC`),
кавычки, регистр, лишние пробелы. Иначе «ООО Ромашка» и «Ромашка» разойдутся.

## Три исхода, а не два

```
similarity ≥ 0.85 и совпал блокинг-признак  →  ДУБЛЬ (склеить)
similarity ≤ 0.55                           →  РАЗНЫЕ
между                                       →  НЕОПРЕДЕЛЁННОСТЬ → ручной разбор
```

Зона неопределённости обязательна. Попытка развести всё одним порогом даёт либо ложные
склейки (потеря данных, необратимая), либо дубли (видимый мусор). Ручной разбор — очередь с
парой записей и подсвеченными признаками; решение оператора сохраняется как **правило**
(эта пара — одно/разное), чтобы не спрашивать снова.

Пороги подбираются на размеченной выборке из своих данных, не берутся из статьи.

## Склейка

- **Каноническая сущность** + связанные `source_record`. Не «удалить дубль», а связать:
  источник может прислать удалённую запись снова, и без связи она вернётся как новая.
- Поля канонической записи выбираются по правилу приоритета источника и свежести, а не
  «последний победил».
- Проверенный факт не затирается непроверенным. Верифицированный сайт не заменяется
  случайной ссылкой из нового прогона.
- Склейка обратима: хранить, что и на каком основании было склеено. Ошибочная склейка без
  истории неразделима.

## Ключ идентичности

```
(source, external_id)              — запись источника, стабильна
canonical_id                       — сущность после склейки
identity_hash                      — детерминированный хэш блокинг-признаков (для быстрого поиска)
```

`identity_hash` не заменяет каскад: он сужает круг кандидатов, решение принимают правила.

## Производительность

Полное попарное сравнение — квадрат. Поэтому блокинг: сначала выбрать кандидатов по
дешёвому признаку (телефон, домен, гео-ячейка, триграммный индекс), потом сравнивать
только их. Без блокинга дедуп на сотне тысяч записей не работает в принципе.

## Тестирование

Обязательный набор — из **реальных** пар, а не выдуманных:

- пара, которую источник прислал дважды с разным написанием;
- сеть с одинаковым названием в разных адресах (**не** дубль);
- разные компании в одном бизнес-центре (**не** дубль);
- компания с общим номером агрегатора (**не** дубль);
- пара из зоны неопределённости (ожидание — попадание в ручной разбор, а не решение).

Каждая ложная склейка из прода становится новым тестом. Это единственный источник роста
набора, который окупается.
