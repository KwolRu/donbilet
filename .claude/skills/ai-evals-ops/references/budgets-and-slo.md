# Бюджеты, лимиты и SLO AI-контура

LLM — единственная часть системы, где **баг стоит денег в реальном времени**. Цикл, который
в обычном сервисе даёт всплеск CPU, здесь даёт счёт.

## Три уровня контроля расходов

| Уровень | Где | Что защищает |
|---|---|---|
| **Потолок задачи** (`executionPolicy.maxCostUsd`) | фасад задач, постфактум | от аномально дорогой одиночной задачи |
| **Бюджет тенанта** (сутки/месяц) | гейт перед тратой | от разорения на одном клиенте |
| **Лимиты шлюза** | конфиг шлюза | от глобального выхода за рамки |

Все три нужны: они ловят разные сценарии.

## Гейт бюджета

```ts
async assertWithinBudget(workspaceId: string): Promise<void> {
  const { dailyLimitUsd, monthlyLimitUsd } = await this.limits(workspaceId);
  const [spentToday, spentMonth] = await Promise.all([
    this.spent(workspaceId, 'day'),
    this.spent(workspaceId, 'month'),
  ]);
  if (dailyLimitUsd && spentToday >= dailyLimitUsd)
    throw new AiBudgetExceededError('day', spentToday, dailyLimitUsd);
  if (monthlyLimitUsd && spentMonth >= monthlyLimitUsd)
    throw new AiBudgetExceededError('month', spentMonth, monthlyLimitUsd);
}
```

Правила:

- **Перед тратой**, а не после. Постфактум-контроль — это отчёт, а не лимит.
- **После идемпотентности**: повтор завершённой задачи денег не тратит, и упирать его в
  лимит нельзя — клиент не сможет забрать собственный результат.
- Источник расхода — **журнал выполнений** (`SUM(cost_usd)`), а не собственный счётчик:
  один источник правды, переживающий рестарты.
- Исчерпание → **402** с цифрами (`spentUsd`, `limitUsd`, `period`). Не 500 и не 429:
  клиент должен понимать, что ретрай не поможет, а поможет пополнение.
- Приёмочный критерий гейта простой и проверяемый: **при исчерпанном лимите новых записей
  выполнения не появляется**.

### Если шлюз умеет бюджеты сам

Использовать нативные бюджеты шлюза, если они доступны в вашем режиме развёртывания.
Частая ловушка: нативные лимиты требуют режима с собственной БД шлюза, который сознательно
не разворачивают — тогда контроль реализуется на своей стороне. Это **осознанное
отклонение**, его надо записать в ADR, а не оставить расхождением между документом и кодом.

## Потолок задачи

```ts
const cost = result?.usage?.costUsd;
if (policy?.maxCostUsd && cost > policy.maxCostUsd) {
  logger.warn(`превышен потолок стоимости ${taskType}: $${cost} > $${policy.maxCostUsd}`);
}
```

Проверяется **постфактум** — до вызова стоимость неизвестна. Не откатываем (деньги уже
потрачены), но громко фиксируем: дорогая задача не должна раствориться в общей сумме и
всплыть только в счёте.

## SLO AI-задачи

| Метрика | Ориентир | Источник |
|---|---|---|
| Успешность (`completed / всего`) | ≥ 97% | журнал |
| Доля `needs_review` | ≤ 2% | журнал |
| Доля невалидного structured output | ≤ 1% | журнал/логи |
| p95 латентности интерактивной задачи | ≤ 8–12 с | журнал (`latency_ms`) |
| p95 фоновой задачи | ≤ 60 с | журнал |
| Стоимость задачи (медиана) | зафиксировать baseline | журнал (`cost_usd`) |
| Дневная стоимость тенанта | ≤ лимита | журнал |

Пороги — **стартовые**. Единственный правильный порог — тот, что посчитан по своему
трафику за 2 недели. Но начинать с чего-то нужно, иначе алертов не будет вообще.

## Экономика: что реально двигает счёт

По убыванию влияния:

1. **Размер входа.** Контекст повторяется в каждом вызове. Урезанный на 30% контекст
   экономит 30% входных токенов на всём трафике.
2. **Число вызовов.** Tool-loop из 3 шагов = 3 вызова с растущим контекстом. Детерминированный
   сбор контекста часто дешевле вдвое.
3. **Выбор маршрута.** Разница между `default` и `fast` — обычно кратная. Задачи, где
   reasoning не нужен, не должны идти на reasoning-модель.
4. **Ретраи.** Free-tier модель с регулярными 429 даёт retry → fallback на **каждом**
   запросе: экономия на модели оборачивается ростом суммарной стоимости.
5. **Повторные генерации.** Идемпотентность — не только про корректность, но и про деньги.

## Деградация под лимитом

Что делать, когда бюджет близок к исчерпанию (описать заранее, а не в момент инцидента):

| Порог | Действие |
|---|---|
| 80% | предупреждение владельцу тенанта, метрика/алерт |
| 95% | перевод неинтерактивных задач на `batch`/`fast`-маршрут |
| 100% | 402 на новые задачи; уже запущенные workflow дорабатывают; интерактивные пути показывают понятную ошибку |

Отдельно: **стоп-флаг тенанта** — ручной глобальный запрет на исходящие действия. Он не
про деньги, а про доверие, и должен работать независимо от бюджета.

## Алерты

Минимальный набор (шаблон — `assets/alert-rules/ai-alerts.yaml`):

- доля `failed` за 15 мин > 10%;
- доля `needs_review` за 1 ч > 5% (маркер деградации модели или атаки);
- p95 латентности за 15 мин выше SLO вдвое;
- дневная стоимость тенанта > 80% лимита;
- дневная стоимость платформы выросла > 50% к среднему за неделю;
- ноль выполнений за час при обычном ненулевом трафике (**молчание — тоже инцидент**).

Последний пункт пропускают чаще всего: сломанный AI-контур часто выглядит как тишина, а не
как ошибки.
