# Evals, guardrails и эксплуатация AI

Главный тезис: **AI-фича без evals и журнала не готова к проду, даже если работает.**
Она работает *сегодня, на этих данных, на этой версии модели* — и нечем доказать, что
завтра это всё ещё так.

## Когда применять

- Перед выкаткой AI-фичи: определить, что считается «работает».
- Регресс: «раньше было лучше», «модель начала выдумывать».
- Смена модели, провайдера, промпта, схемы контекста.
- Вопросы стоимости, лимитов, алертов, инцидентов.
- Инциденты: утечка, инъекция, шторм ошибок, всплеск расходов.

## Когда НЕ применять

- Строим слой с нуля, вопрос про шлюз/фасад/tools → `ai-layer-architecture`.
- Вопрос про сервисные границы, tenancy, Temporal, OPA как инфраструктуру →
  `platform-architecture`.

## Инварианты (нарушение = ошибка ревью)

1. **Жёсткие запреты — детерминированной политикой на выходе, не промптом.** Промпт —
   вероятностная просьба; запрет должен быть проверяемым и одинаковым для всех вызовов.
2. **Guardrails слоисты и разделены**: INPUT (границы, обрамление), AGENT (шаги, таймаут,
   токены), TOOL (authz, аудит — в самом инструменте), OUTPUT (утечки, запреты).
   Слои не дублируются: дубль = два места, где чинить, и одно, где забудут.
3. **Safe failure**: сомнительный выход не «подчищается», а отклоняется в `needs_review`.
   Отдать наружу отфильтрованный мусор хуже, чем не отдать ничего.
4. **Fail-closed по умолчанию.** Недоступна политика → запрет. Исключения — только явные,
   обоснованные и описанные (см. `references/guardrails.md` → «Когда fail-open допустим»).
5. **Бюджет проверяется ПЕРЕД тратой**, исчерпание = отдельный код ответа (402), а не 500.
6. **Каждое выполнение — в журнале**, включая провалы. Иначе success rate считается по
   выжившим, а стоимость — по половине трафика.
7. **Evals детерминированы там, где это возможно.** LLM-as-judge — дополнение к
   детерминированным проверкам, никогда не единственный критерий.
8. **Golden-датасет содержит adversarial-кейсы.** Набор только из «хороших» примеров
   доказывает лишь то, что код запускается.
9. **Зелёный тест на пустых/мусорных данных — не зелёный.** Проверка обязана падать, если
   входных данных нет; иначе она измеряет саму себя.
10. **Prompt/PII/секреты не попадают в атрибуты спанов и логи.**

## Порядок работы

1. **Определить критерии** до кода: что для этой задачи «правильный ответ», какие ошибки
   критичны, а какие — стилистические.
2. **Написать детерминированные evaluators** (чистые функции без LLM):
   schema validity, grounding, отсутствие выдуманных сущностей, запреты, утечки, язык, стиль.
3. **Собрать golden-датасет**: positive + adversarial + edge. Минимум 6–10 кейсов на задачу,
   с фиксированными ожиданиями *какой именно evaluator должен упасть*.
4. **Прогнать harness на фикстурах** — так проверяются сами evaluators, а не модель.
5. **Прогнать live** на реальном агенте, сохранить evidence-JSON.
6. **Подключить guardrails** по слоям и запреты — в политику.
7. **Поставить бюджет и SLO**, алерты по метрикам из журнала.
8. **Зафиксировать baseline**: числа прогона в evidence. Дальше любое изменение модели или
   промпта сравнивается с baseline, а не с ощущением.

## Правила assets

- `assets/eval-suite/` — `evaluators.ts`, `golden.ts`, `run-eval.ts` (CLI, пишет
  evidence-JSON), `guardrails.ts`, `budget.ts`. Копировать и адаптировать evaluators под
  предметную область: **список проверок задаче-специфичен**, каркас — нет.
- `assets/alert-rules/ai-alerts.yaml` — правила алертов; пороги обязательно пересчитать
  под свой трафик, дефолты в файле — стартовые.
- `assets/dashboards/ai-overview.md` — панели с готовыми SQL/PromQL по журналу выполнений.
- `assets/incident-template.md` — шаблон разбора; заполняется по факту, не по памяти.

## Чеклист перед прод-выкаткой AI-фичи

- [ ] Есть golden-датасет с adversarial-кейсами; harness воспроизводим одной командой.
- [ ] Прогон на фикстурах доказывает, что evaluators **ловят** нарушения (а не только
      пропускают хорошее).
- [ ] Live-прогон сохранён как evidence с числами и версиями (модель, промпт, знания).
- [ ] Запреты реализованы политикой, а не только текстом промпта.
- [ ] Output-фильтр утечек читает реальный реестр секретов, а не только `process.env`.
- [ ] Бюджет тенанта настроен; исчерпание отдаёт 402 и НЕ создаёт новых выполнений.
- [ ] Журнал содержит физическую модель, стоимость, версию промпта, статус — и для провалов.
- [ ] Алерты: доля ошибок, доля `needs_review`, p95 латентности, дневная стоимость.
- [ ] Понятно, что делать при недоступности провайдера (деградация описана, а не «упадём»).
