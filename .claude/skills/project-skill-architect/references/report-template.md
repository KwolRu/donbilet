# Шаблон отчёта

Структура обязательна и неизменна: по ней отчёты разных запусков сравнимы между собой.

**Правило доказательств.** Любое число, утверждение о дублях и оценка полноты покрытия
сопровождаются командой или ссылкой на файл. Без evidence формулировать качественно
(«часть скиллов дублируется»), а не количественно («дублей 12»).

---

## 1. Вердикт

3–5 предложений: состояние портфеля, главный риск, что делать первым. Без списков.

## 2. Карта проекта (проверенная)

| Слой | Что найдено | Подтверждение |
|---|---|---|
| Сервисы/пакеты | | путь |
| Данные и миграции | | путь |
| Контракты | | путь |
| Вход и аутентификация | | путь |
| Внешние интеграции | | путь |
| Процессы и оркестрация | | путь |
| Фронт и дизайн | | путь |
| Тесты и приёмка | | путь |
| Локальный запуск и деплой | | путь |

Строки без подтверждения сюда не попадают — им место в разделе 3 как выводам.

## 3. ТЗ и противоречия

**Главное ТЗ:** путь, версия, на каком основании выбрано.
**Сопутствующие документы:** роадмап, ADR, живой статус, инструкции агентам.

**Подтверждённые факты** — что проверено в коде и совпало.

**Выводы** — что следует из фактов, но напрямую не проверялось.

**Неразрешённые противоречия:**

| Что | В документе | В коде | Класс | Влияние на портфель |
|---|---|---|---|---|
| | ссылка | ссылка | устаревшее / опережающее / противоречие / легаси | |

## 4. Инвентаризация инструкций и скиллов

Команда, которой получены данные, — обязательно.

| Скилл | Размещение | `description` | Размер | Соответствие коду | Замечания |
|---|---|---|---|---|---|

Отдельно перечислить:
- каталоги без `SKILL.md` (не являются скиллами);
- заглушки и `TODO`;
- побайтовые дубли между размещениями;
- одноимённые скиллы с разным содержимым;
- битые ссылки на references.

## 5. Решения по каждому скиллу

| Скилл | Вердикт | Почему | Что именно сделать |
|---|---|---|---|
| | keep / update / replace / add / archive / relocate | | |

Вердикты `archive` и `relocate` помечаются как **требующие отдельного разрешения**.

## 6. Пробелы покрытия

По каждой области из рубрики — состояние и доказательство.

| Область | Состояние | Доказательство | Кандидат |
|---|---|---|---|
| … | покрыто / частично / пробел | путь, команда, наблюдение | имя скилла или «не нужен» |

Пробел без доказательства пробелом не считается.

## 7. Рекомендуемый портфель

Итоговый список после применения решений — как он должен выглядеть.

| Скилл | Главный вопрос | Размещение | Статус |
|---|---|---|---|
| | | глобально / репозиторий | существует / обновить / создать |

## 8. Размещение и канонизация

- Что переезжает и куда, с обоснованием.
- Версионируются ли проектные скиллы (проверка `.gitignore` с командой).
- Если репозиторий обслуживают несколько агентских систем — какой источник канонический и
  как синхронизируется.

## 9. Волны

**Волна 1** — что делать сейчас, с обоснованием приоритета.

**Волна 2** — что следующим.

**Backlog** — прошедшие критерии, но без текущего сценария. Для каждого — **условие
запуска**: конкретное событие, при наступлении которого скилл становится нужен. Backlog
без условий запуска не фиксируется.

## 10. Сценарии проверки

По каждому создаваемому/обновляемому скиллу:

| Скилл | Должен сработать | Не должен сработать | Проверка полезности |
|---|---|---|---|

## 11. Разрешения

**Выполнено в этом запуске:** перечислить фактические изменения (в Audit/Plan — «ничего»).

**Разрешено выполнять без дополнительного подтверждения:** создание и обновление
утверждённых скиллов в Build.

**Требует отдельного явного разрешения:**
- удаление, перемещение, архивация существующих скиллов;
- изменение `.gitignore`;
- изменение файлов вне каталогов скиллов (включая `CLAUDE.md`/`AGENTS.md`);
- установка внешних скиллов из сторонних источников.

---

## Форма подачи

- Отчёт — в ответе, не файлом, если пользователь не попросил файл.
- Таблицы вместо списков там, где есть несколько измерений.
- Сначала вердикт, потом доказательства: читающий должен понять итог за 20 секунд.
- Не пересказывать содержимое скиллов — только выводы о них.
