# Выбор стека и замены компонентов

Правило: **сначала требования и инварианты, потом технологии.** Если проект уже использует
конкретный стек — продолжать с ним. Если стек не определён — предлагать профиль по
умолчанию, явно называя компромиссы.

## Профиль по умолчанию

| Назначение | Выбор по умолчанию | Почему |
|---|---|---|
| Model gateway | **LiteLLM Proxy** | OpenAI-совместимый API, маршрутизация, fallback, cost tracking из коробки |
| Agent runtime | **Mastra** | agent loop, tool calling, structured output; за фасадом — заменим |
| Tool protocol | **MCP** | единый стандарт инструментов для агентов и для интеграций |
| Policy engine | **OPA / Rego** | policy-as-code, тестируемые правила, изменение без релиза |
| Durable workflows | **Temporal** | durable execution, сигналы, длинные паузы, история |
| Простые фоновые задачи | **BullMQ** | дёшево, уже есть Redis |
| Secrets | **Vault** | изоляция по путям, ротация без релиза |
| AI-телеметрия | **Langfuse** | разборы генераций, сравнение промптов |
| Трассировка | **OpenTelemetry** | вендор-нейтральна, экспорт куда угодно |
| БД | **PostgreSQL** (+ pgvector при необходимости) | один движок вместо трёх |

Это **профиль реализации, а не догма**. Каждый компонент — цена: процесс, конфигурация,
знания команды. Брать только тот, чью способность действительно нужно закрыть.

## Замены по способностям

Сравнивать надо не названия, а **необходимые гарантии**.

| Назначение | По умолчанию | Возможные замены | Что проверить перед заменой |
|---|---|---|---|
| Model gateway | LiteLLM | прямой SDK, Portkey, OpenRouter | маршрутизация алиасов, fallback между **семьями**, cost в ответе, единый ключ |
| Agent runtime | Mastra | LangGraph, чистый SDK + свой цикл | structured output, tool calling, контроль шагов, доступ к телеметрии вызова |
| Tool protocol | MCP | внутренние typed tools | единая схема, authz на границе, аудит, переиспользование вне агентов |
| Policy engine | OPA | Cerbos, Casbin, код | внешние данные в решении, тесты политик, изменение без релиза, внятная причина отказа |
| Durable workflows | Temporal | Inngest, Restate, BullMQ+БД | **см. таблицу гарантий ниже** |
| Secrets | Vault | AWS/GCP Secret Manager, SOPS | изоляция путей по сервисам, ротация, аудит доступа |
| AI-телеметрия | Langfuse | Helicone, чистый OTel | связь с журналом выполнений, стоимость, версии промптов |
| Векторный поиск | pgvector | Qdrant, Weaviate, pinecone | tenant-фильтр в запросе, объём, латентность, транзакционность с бизнес-данными |
| Поиск | Postgres FTS | Elasticsearch/OpenSearch | объём, требования к релевантности, цена отдельного кластера |

## Замены НЕ эквивалентны

Самая частая ошибка — считать строки таблицы взаимозаменяемыми. Проверять надо гарантии.

**BullMQ вместо Temporal** закрывает только «ретрай задачи». Не закрывает:

| Гарантия | BullMQ | Что придётся построить |
|---|---|---|
| Состояние между шагами | ✗ | своя таблица состояний + переходы |
| Пауза 7 дней | ~ (delayed job) | восстановление после рестарта, отмена |
| Ожидание внешнего сигнала | ✗ | поллинг или своя таблица ожиданий |
| Replay после падения | ✗ | ручное восстановление позиции |
| Компенсация | ✗ | своя saga-машина |
| История/аудит | логи | своя таблица событий |
| Human-in-the-loop | ✗ | своя очередь approve + таймауты |

Если из этого списка нужны 3+ пунктов — вы строите Temporal вручную, только хуже и без
тестов. Если нужен 0 — Temporal избыточен.

**Прямой SDK вместо шлюза** закрывает «вызвать модель». Не закрывает: смену провайдера
конфигом, каскад fallback, единый учёт стоимости, единый ключ, наблюдаемость физической
модели. На одной модели это незаметно; на второй — уже дорого.

**Код вместо policy engine** работает, пока правил < 5 и меняются они раз в квартал.
Дальше: изменение правила = релиз, аудит решений отсутствует, «почему не отправилось»
собирается по логам.

## Правила миграции

1. **Не мигрировать без причины.** Причина формулируется как отсутствующая гарантия, а не
   как «X современнее».
2. **Мигрировать за фасадом.** Если компонент был за адаптером/фасадом — миграция
   локальна. Если не был — сначала завести фасад, потом мигрировать.
3. **Параллельный период.** Старое и новое работают одновременно, трафик переключается
   долей, метрики сравниваются.
4. **Обратная совместимость данных.** История выполнений/событий не теряется: либо
   мигрируется, либо остаётся доступной на чтение.
5. **Критерий отката** формулируется ДО начала: при каких числах возвращаемся.
6. **ADR на миграцию** с разделом «что оказалось не так» после завершения.

## Когда добавлять компонент, а когда терпеть

Добавлять, когда:
- отсутствующая гарантия уже вызвала инцидент или блокирует требование;
- своя реализация заняла бы больше времени, чем эксплуатация готового;
- команда способна его эксплуатировать (не только запустить).

Терпеть, когда:
- компонент решает проблему, которой ещё нет («потом пригодится»);
- закрывает 10% задачи, а 90% всё равно писать самим;
- в команде нет никого, кто отладит его в 3 часа ночи.

Каждый лишний процесс в инфраструктуре — это ещё один способ упасть в проде и ещё один
пункт в чеклисте развёртывания.

## Профиль «минимальный старт»

Если продукт только начинается, а инварианты сохранить нужно:

```
Postgres + один API-сервис + BullMQ
Шлюз моделей: LiteLLM (единственный внешний компонент — он окупается сразу)
Политики: код, но ИЗОЛИРОВАННЫЙ модуль с тем же контрактом, что у PEP
Секреты: env + запрет коммита, загрузчик с единым контрактом
Durable: нет; процессы одношаговые
```

Ключ: **контракты уже правильные**, реализации простые. Тогда переход на OPA/Temporal/Vault
позже — замена реализации за фасадом, а не переписывание системы.
