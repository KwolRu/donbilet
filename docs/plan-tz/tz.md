## 1. Предмет

Исполнитель выполняет переработку личного кабинета, редизайн сайта и реализацию функциональных доработок donbilet.ru согласно составу работ раздела 2.

## 2. Состав работ

### 2.1. Мои билеты
Список купленных билетов: маршрут, дата и время, станция отправления и прибытия, место, данные пассажира, стоимость, статус возврата. Скачивание PDF **с проверкой принадлежности билета текущему авторизованному пользователю**. Оформление возврата с подтверждением кодом. Скрытие билета из списка без удаления записи заказа.

Экран: список карточек в разделе «Мои билеты». Карточка свёрнута по умолчанию (заголовок: маршрут, дата), клик разворачивает детали. Поля: город/вокзал отправления и прибытия, дата и время отправления/прибытия, номер рейса, место (и платформа для автобуса), ФИО и документ пассажира, гражданство, пол, дата рождения, итоговая стоимость, номер заказа, статус возврата.

Кнопки: «Скачать билет» (PDF); «Вернуть билет» (попап возврата, **не отображается, если дата отправления прошла**); «Удалить» (скрывает билет, запись заказа не удаляется, с попапом «Вы уверены?»).

Сценарий возврата: попап с условиями (сумма к возврату, удержания) → «Запросить код» (email/телефон) → поле кода (цифры, фиксированная длина) → «Подтвердить возврат» неактивна при пустом поле → при неверном коде сообщение под полем.

### 2.2. История поездок
Список завершённых поездок с составом данных по п. 2.1. «Повторить поездку» — переход к поиску с предзаполненными городами отправления/прибытия и сегодняшней датой. «Удалить из истории» — мягкое скрытие. Кнопок «Скачать»/«Вернуть» нет.

### 2.3. Сообщения
Уведомления по событиям: изменение статуса возврата билета; отмена или перенос рейса (фиксируется сотрудником через панель администрирования). Отметка сообщения как прочитанного.

Экран: список карточек — заголовок, дата, краткий текст. Непрочитанные визуально выделены. Клик разворачивает полный текст и помечает прочитанным.

Источники: «Возврат подтверждён/отклонён» — автоматически; «Рейс отменён/перенесён» — только вручную сотрудником, автоматического источника от перевозчиков нет. Раздел информационный, ответить нельзя (переписка — в 2.14).

### 2.4. Профиль
Просмотр email (только отображение, неактивным стилем). Редактирование телефона и пароля. Валидация: телефон `+7XXXXXXXXXX` с маской; пароль + повтор со сверкой. Кнопки «Сохранить» (неактивна при ошибке) и «Отмена».

### 2.5. Избранное
Избранные направления (пара городов без даты) и избранные билеты (конкретный рейс с датой, временем и перевозчиком). Переход к поиску с предзаполненными данными. Автоматическое исключение записей с прошедшей датой или изменившимся рейсом.

Добавление: иконка «сердце» рядом с полями городов на форме поиска (направление) и на карточке рейса в результатах (билет). Раздел ЛК с блоками «Направления» и «Билеты». Правило устаревания: прошедшие/изменившиеся рейсы тихо исключаются без сообщения об ошибке.

### 2.6. Пассажиры
Данные пассажиров, привязанных к аккаунту (фамилия, имя, отчество, пол, дата рождения, тип и номер документа, гражданство), **до 10 записей на аккаунт**. Добавление, редактирование, удаление. Выбор сохранённого пассажира при оформлении заказа.

Форма: Фамилия*, Имя*, Отчество (чекбокс «Нет отчества»), Пол*, Дата рождения* (календарь), Тип документа* (паспорт РФ, свидетельство о рождении, загранпаспорт и т.д.), Серия и номер*, Гражданство* (по умолчанию Россия).

Валидация: ФИО только буквы; дата рождения не в будущем; формат серии/номера зависит от типа документа. При попытке добавить 11-го — «Достигнут лимит 10 сохранённых пассажиров, удалите одного из существующих».

На экране оформления: выпадающий список «Выбрать из сохранённых» с автозаполнением и возможностью донастройки.

### 2.7. Отель по городу прибытия
Блок бронирования отеля на экране подтверждения покупки, партнёрская интеграция. Виджет с автоподстановкой города прибытия и дат (дата прибытия — заезд, +1 день — выезд по умолчанию). Оформление брони — на стороне партнёра.

### 2.8. Оценка перевозчика
Выставление оценки после поездки, **с проверкой принадлежности билета оценивающему пользователю**. Сбор и выгрузка данных в панели администрирования с фильтрацией по перевозчику, маршруту и периоду, в формате CSV.

Экран: в карточке прошедшей поездки блок «Оцените поездку», после оценки заменяется на «Спасибо за оценку». Элемент: 5 звёзд. Запрос с чужим ID билета отклоняется.

Панель администрирования: таблица (дата, перевозчик, маршрут, оценка), фильтры, кнопка «Выгрузить в CSV».

### 2.9. Авторизация через VK ID и Яндекс ID
Вход и регистрация через VK ID и Яндекс ID. Автоматическое определение существующего аккаунта по email от провайдера. Запрос email вручную, если провайдер его не предоставил.

Сценарий: клик → авторизация у провайдера → возврат → email совпал с существующим аккаунтом — вход; email новый — создание аккаунта и немедленный вход. Граничный случай: нет email → форма «Введите email для завершения регистрации».

### 2.10. Подтверждение email при регистрации
Покупка билета **не требует** подтверждения email — учётная запись может создаваться без кода.

Прямая регистрация через форму «Зарегистрироваться» требует подтверждения: email/телефон/пароль → код подтверждения (**срок действия 15 минут**, **повторная отправка не чаще раза в 60 секунд**) → активация и автоматическая авторизация.

Если доступ в ЛК получен без подтверждённого email — в ЛК отображается уведомление с предложением подтвердить адрес.

Экран: форма (email*, телефон, пароль*, повтор пароля*) → «Зарегистрироваться» → «Введите код» (поле, «Подтвердить», «Отправить код повторно» с обратным отсчётом 60 с) → переход в ЛК.

Правила: код истёк → «Код истёк, запросите новый»; email занят → «Этот email уже зарегистрирован» со ссылкой на вход/восстановление.

### 2.11. Страховка
Отдельный блок в завершающей части оформления заказа, **перед экраном оплаты**, **во всех сценариях оформления заказа**.

Экран: отдельный шаг между данными пассажиров/услуг и оплатой — карточка «Страхование поездки»: условия, ссылка «подробнее», сумма, переключатель «Добавить страховку» (состояние по умолчанию явное, не скрытое предвыбранное).

Логика: включение добавляет сумму к итоговой стоимости на этом же экране и переносит её на оплату; выключение — убирает.

### 2.12. Новости
Раздел новостей с панелью администрирования (заголовок, текст, изображение, дата публикации) и постраничным выводом. **Формирование RSS-фида в формате, поддерживаемом сервисом «Дзен»**, для автоматической синдикации в канал Заказчика.

Публично: список карточек (изображение, заголовок, дата, анонс) с пагинацией; отдельная страница публикации.

Админка: список (добавить/редактировать/удалить/скрыть), форма: заголовок*, текст* (с форматированием), изображение, дата публикации* (можно будущей — отложенная публикация).

### 2.13. Справочная
FAQ с группировкой по категориям («Покупка», «Возврат», «Общие вопросы») и панелью администрирования. Вопрос — строка-аккордеон. Админка: добавление/редактирование/удаление, привязка к категории, изменение порядка отображения.

### 2.14. Поддержка
Чат на сайте и в ЛК. Для авторизованных номер телефона не запрашивается. Ответы — сотрудником через панель администрирования, **с доставкой сообщений в реальном времени**.

Экран: плавающая иконка на всех страницах. Неавторизованный: перед первым сообщением обязательное поле «Ваш номер телефона», кнопка «Начать чат». Авторизованный: сразу окно ввода, контакты из аккаунта.

Диалог: поле ввода + «Отправить», история в хронологическом порядке с отметкой времени.

Админка: список обращений (открытые/закрытые), окно диалога с историей и полем ответа, кнопка «Закрыть обращение».

### 2.15. Бот в мессенджере MAX
Поиск рейсов и оформление покупки, включая оплату, в диалоге бота. Выбор места — из списка (без графической схемы). Данные пассажира — пошагово, с возможностью выбора сохранённого пассажира (2.6) для авторизованных. Билет — файлом в диалоге.

Оплата: нативный механизм платформы MAX при его наличии, либо переход по защищённой платёжной ссылке на экран сайта — без повторного ввода платёжных данных, страница оплаты та же, что на сайте.

Сценарий: приветствие («Найти билет» / «Мои билеты» / «Помощь») → город отправления → город прибытия → дата («Сегодня»/«Завтра»/ввод) → список рейсов → выбор рейса → список мест → данные пассажира → итоговая сумма + «Оплатить» → оплата → PDF в диалог.

### 2.16. Брендинг
Единая визуальная айдентика: логотип (основной, монохромный, для тёмного фона), цветовая палитра (с HEX-кодами), типографика (шрифт, размеры заголовков и текста), базовый UI-кит (кнопки в состояниях обычная/наведение/неактивная, поля ввода, переключатели, карточки). Применяется на всех разделах, включая главную. Основа для пп. 2.17–2.20.

### 2.17. Редизайн раздела ЖД
Визуальное переоформление существующих экранов (форма поиска, список результатов, страница бронирования) под UI-кит из 2.16. Функциональность и бизнес-логика не меняются.

### 2.18. Редизайн раздела Авто
Аналогично 2.17.

### 2.19. Редизайн раздела Отели
Аналогично 2.17.

### 2.20. Редизайн раздела Авиа
Аналогично 2.17–2.19. **Точный объём сопутствующих технических работ определяется по результатам технического аудита существующей реализации, проводимого Исполнителем до начала работ по настоящему пункту.**

### 2.21. Блок кросс-перехода между разделами
Блок на странице результатов поиска с переходом в раздел ЖД или Авиа, с предзаполненными городами. Отображение перехода в Авиа — по перечню направлений с подтверждённым авиасообщением, определяемому и обновляемому Заказчиком через панель администрирования (список пар городов с переключателем вкл/выкл).

Экран: после списка найденных рейсов — карточка «Посмотрите также рейсы ЖД/Авиа в этом направлении», кнопка «Искать» (без даты — пользователь указывает сам).

### 2.22. Отель на странице результатов поиска
Блок «Отель в [город прибытия]» между карточками результатов — фото, название, цена за ночь, кнопка «Выбрать». Выбор добавляет отель отдельной позицией в заказ (аналогично страховке 2.11): сумма прибавляется к итоговой, отображается отдельной строкой на экране оплаты с возможностью убрать. Оплата отеля — в общем платеже с билетом; документ по услуге отеля формируется отдельно.

### 2.23. Промокоды
Создание кода, скидка (в процентах или фиксированной суммой), срок действия, **лимит использований**. Применение **на экране оплаты заказа**. Управление через панель администрирования.

Экран: поле «Промокод» + «Применить». Успех — «Промокод применён: −N ₽ / −N%», пересчёт итоговой суммы. Ошибки: «Промокод не найден» / «Срок действия истёк» / «Промокод уже использован».

Админка: список (код, тип скидки, размер, срок, лимит, статус, счётчик применений), форма создания (вручную или автогенерация), «Деактивировать». Одноразовый промокод после применения деактивируется автоматически — по пользователю или в целом, в зависимости от типа лимита.

### 2.24. Уведомление о снижении цены
Письмо на email при снижении цены билета, сохранённого в «Избранном» (2.5). Фоновая периодическая проверка. Тема «Цена на ваш билет снизилась», детали рейса и ссылка для перехода к покупке.

### 2.25. Напоминание о поездке
Автоматическое письмо за установленное время до отправления (**значение задаётся в настройках**): маршрут, дата и время, место, вокзал/станция отправления, рекомендация «что взять с собой».

### 2.26. Билет «туда-обратно» одной покупкой
Оформление двух прямых рейсов (А→Б и Б→А) единой покупкой с единой стоимостью, поверх двух самостоятельных бронирований. Согласованное управление сроком действия обеих броней. Дата обратного рейса указывается пользователем.

Экран: переключатель «В одну сторону» / «Туда-обратно»; поле «Дата обратного рейса» (минимальная дата — не раньше даты рейса «туда»). Результаты показывают рейс «туда» и подборку «обратно». Данные пассажиров вводятся один раз для обоих сегментов. Единый экран оплаты, единая сумма, единый номер заказа.

**Правило при сбое:** если второй сегмент забронировать не удалось — первый сегмент автоматически отменяется, показывается «Не удалось забронировать обратный рейс, попробуйте другую дату», **списание оплаты не происходит**.

## 3. Технические требования

**3.1.** Серверная часть, дублированная в двух программных модулях, консолидируется в единый модуль.

**3.2.** API, используемый мобильным приложением Заказчика, сохраняет полную обратную совместимость — действующая версия приложения продолжает работать без изменений на своей стороне.

**3.3.** Управление содержимым и данными по пунктам 2.3, 2.7, 2.8, 2.12, 2.13, 2.14, 2.15, 2.21, 2.23 осуществляется через **отдельную панель администрирования, выполненную как самостоятельный интерфейс для нетехнического персонала** (не встроенная техническая консоль платформы).

**3.4.** Доработки, затрагивающие форму оформления заказа (2.11, 2.22, 2.23), применяются **единообразно во всех сценариях оформления заказа**.

**3.5.** Визуальное оформление разделов личного кабинета выполняется в соответствии с айдентикой по п. 2.16.

## 4. Не входит в объём работ

**4.1.** Изменения мобильного приложения, кроме поддержания совместимости API (3.2).
**4.2.** Автоматизация ответов в чате поддержки средствами ИИ.
**4.3.** Накопительная система (кошелёк, уровни, кэшбек).
**4.4.** Личный кабинет для юридических лиц.
**4.5.** Сохранение банковских карт, Apple/Google Wallet, реферальная программа, ускоренное повторное оформление в 1–2 действия, персонализированный главный экран ЛК, подтверждение входа с нового устройства, групповые/семейные заказы.
**4.6.** Полноценная графическая схема мест в диалоге бота (2.15).
**4.7.** Публичное отображение отзывов и оценок на сайте (2.8).
**4.8.** Динамическое ценообразование.
**4.9.** Рейсы с пересадкой.

## 5. Результат и приёмка

**5.1.** Результат — личный кабинет и сайт donbilet.ru, реализующие функциональность по пп. 2.1–2.26, размещённые в рабочем окружении Заказчика.

**5.2.** **Приёмка выполняется по каждому пункту раздела 2 отдельно**, путём проверки соответствия реализованной функциональности описанию пункта.

## 6. Разграничение ответственности

Исполнитель отвечает за соответствие результатов ТЗ. Заказчик — за своевременное предоставление материалов, доступов и согласование промежуточных результатов **в срок не более 3 (трёх) рабочих дней**. Изменения за рамками ТЗ — дополнительные работы, оплачиваются отдельно.
