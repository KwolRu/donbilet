# Структура приложения и границы рендеринга

## Route groups

```
app/(auth)/      login, register     — публичная зона, свой layout
app/(app)/       рабочая зона        — оболочка «Mission Control», требует сессии
app/api/         серверные обработчики (в URL присутствует как /api/...)
```

Скобочные сегменты не влияют на URL: `app/(app)/leads/page.tsx` → `/leads`. Они существуют
ради **разных layout'ов**: вход не должен рисовать боковое меню, рабочая зона не должна
рисовать форму входа.

Новый раздел рабочей зоны кладётся в `app/(app)/<раздел>/`:

```
app/(app)/leads/
  page.tsx           серверный компонент по умолчанию
  layout.tsx         только если у раздела своя оболочка
  loading.tsx        скелет на время загрузки сегмента
  error.tsx          граница ошибок сегмента ("use client" обязателен)
  [id]/page.tsx      деталь
```

## Server / client

По умолчанию компонент **серверный**. `"use client"` добавляется, только когда нужен
`useState`/`useEffect`/обработчик события/браузерный API.

Практическое правило: страницы рабочей зоны интерактивны (фильтры, карта,
инбокс), поэтому их «мясо» клиентское, но **обёртка остаётся серверной** — она решает
метаданные и раскладку, не тянет в бандл стор.

```tsx
// app/(app)/leads/page.tsx  — сервер
export const metadata = { title: "Лиды" };

export default function LeadsPage() {
  return <LeadsScreen />;          // клиентский компонент со стором
}
```

Что нельзя протаскивать через границу: функции, классы, `Date` внутри сложных структур,
`Map`/`Set` — только сериализуемые данные.

Серверные переменные окружения в клиентском компоненте недоступны физически: доступ к ним
из `"use client"` даёт `undefined` в браузере, а не ошибку сборки — поэтому проверять надо
явно, через `lib/env`.

## Загрузка, пустота, ошибка

Три состояния, которые забывают в таком порядке: **пусто**, **ошибка**, **загрузка**.

```tsx
if (loading) return <Skeleton />;
if (error)   return <ErrorState message={error} onRetry={load} />;
if (!items.length) return <EmptyState title="Пока нет лидов" hint="Запустите сбор" />;
return <LeadTable items={items} />;
```

«Пусто» и «загрузка» должны различаться визуально: пустой список, отрисованный как спиннер,
выглядит как зависание. Компоненты состояний: `ui/skeleton`, `ui/error-banner`, `common/empty-state`.

`error.tsx` сегмента ловит то, что упало при рендере; ошибки запросов ловит стор и кладёт в
`error`. Это разные механизмы, нужны оба.

## Навигация и роутинг

- Пути — через константы в `lib/routing/`, а не строками по компонентам: переименование
  раздела иначе превращается в поиск по репозиторию.
- Редиректы после входа — через `?next=`, который ставит `proxy.ts`.
- Параметры списка (фильтры, сортировка, страница) держать в URL, а не только в сторе:
  иначе ссылка на отфильтрованный список не работает, а F5 сбрасывает работу.

## Переменные окружения

```
lib/env/           единственное место, где читается process.env
```

- Серверные — без префикса, доступны только в серверных файлах.
- Клиентские — `NEXT_PUBLIC_*`, **попадают в бандл** и видны пользователю.
- Отсутствие обязательной переменной должно приводить к явной ошибке при старте, а не к
  `undefined`, всплывающему в рантайме через неделю.

## Файлы верхнего уровня

| Файл | Роль |
|---|---|
| `proxy.ts` | guard оболочки (в Next.js 16 это переименованный `middleware.ts`, экспорт `proxy()`) |
| `server.js` | кастомный dev-сервер: Next.js + прокси /api → gateway |
| `next.config.ts` | конфигурация сборки |
| `tailwind.config.ts`, `assets/styles/global.css` | токены дизайн-системы проекта |

`bun run dev` запускает `node server.js`, а не `next dev` — это важно помнить при отладке
запуска и при чтении логов.

## Куда что класть

| Что | Где |
|---|---|
| Схема ответа, доменные константы | `app/core/validators/` |
| Запрос к API | `app/core/api/` |
| Общее состояние экрана | `app/core/store/` |
| Переиспользуемый UI | `components/ui` (примитивы), `components/common` (составные) |
| Чистая утилита | `app/core/utils/` — и на неё пишется `node --test` |
| Хук | `app/core/hooks/` |
| Пути, редиректы, политика ошибок | `lib/routing/` |
