# Страница `/order`: frontend handoff

Страница реализует три шага покупки автобусного билета — выбор мест, заполнение
данных пассажиров и форму оплаты. Сейчас это чистый frontend на моках, без
подключения API и платёжного шлюза.

## Расстановка блоков

Базовый макет рассчитан на ширину `1920px`.

- Header — общий `SiteHeader`, высота `72px`.
- Центральный контейнер — `1220px`, по `350px` слева и справа.
- Верхняя строка: ссылка «Поиск билетов» слева, прогресс оформления `600px`
  справа.
- Ниже через `24px`: заголовок страницы слева и таймер бронирования справа.
- Ещё через `24px`: две карточки в одной строке.
- Карточка выбора мест — `755px`.
- Промежуток между карточками — `20px`.
- Карточка заказа — `445px`.
- Итого: `755 + 20 + 445 = 1220px`; обе крайние границы совпадают с
  границами центрального контейнера.
- Footer начинается на координате `y = 1036px` в полотне `1920×1371`.

Для десктопных окон уже `1920px` весь checkout пропорционально уменьшается
через класс `order-design-viewport`. Благодаря этому блоки сохраняют размеры и
позиции относительно Figma, не появляется горизонтальный скролл.

## Переключатель выбора

Использован общий компонент `SegmentedControl`.

- Размер контейнера — `609×40px`.
- Внутренний отступ — `4px`.
- Две равные кнопки высотой `32px`.
- У общего контейнера нет бордера и тени.
- Активная кнопка жёлтая, неактивная белая.
- Режим «Выбор из списка» разрешает нажимать места.
- Режим «Автоматический выбор мест» заменяет карту блоком выбора количества
  пассажиров. Счётчик работает в диапазоне от 1 до 10 и имитирует автоматическое
  назначение доступных мест.

Этапы прогресса — обычные круглые pill-кнопки `rounded-full`, без squircle:
это отдельное исключение из общих правил радиусов, заданное макетом.

## Карта мест

Карта собрана HTML/CSS, отдельная картинка не используется.

- Общий корпус — `664×264px`.
- Салон занимает первые `600px`, нос автобуса — последние `64px`.
- Корпус является одним элементом, поэтому между салоном и носом нет разрыва.
- Внутри салона сетка `12×5`.
- Размер места — `40×40px`, промежуток — `8px`.
- Пустые ячейки `null` формируют проход.
- Недоступные места `"unavailable"` отображаются диагональной штриховкой.
- В макете 8 недоступных ячеек.
- Изначально выбраны места `25`, `29`, `30`.
- Выбранное место жёлтое, доступное — светло-серое.
- Максимум мест равен текущему количеству пассажиров (изначально — 3).

Матрица мест хранится в `MOCK_ORDER.seatColumns`, а логика выбора — в
`useOrderStore`.

## Правая карточка заказа

Карточка состоит из двух белых секций одинаковой ширины `445px`:

1. Рейс, даты, время, вокзалы, длительность, выбранные места и ссылки на
   условия.
2. Общая цена, разбивка стоимости и кнопка продолжения.

Между секциями — пунктирная линия и круглые билетные вырубки. Реализовано CSS-
масками `order-notch-top`, `order-notch-bottom` и
`order-perforation-horizontal`.

На шаге пассажиров нижняя секция показывает расширенную разбивку с багажом и
страхованием, три обязательных согласия и кнопку продолжения. На шаге оплаты
тот же состав сохраняется, а CTA меняется на «Оплатить».

## Данные пассажиров

После кнопки «Ввести данные пассажиров» экран переключается на второй шаг без
смены URL. Этапы «Выбор места» и «Пассажиры» в прогрессе становятся жёлтыми.

- На каждого пассажира отображается отдельная карточка, связанная с выбранным
  местом.
- Доступны редактируемые ФИО, пол, дата рождения, гражданство, документ и его
  номер.
- Кнопка «Выбрать пассажира» открывает правый сайдбар `476px` со списком из
  мокового личного кабинета. Выбор пассажира или конкретного документа
  подставляет данные в текущую форму и закрывает панель.
- Страхование и багаж переключаются отдельно; у багажа есть счётчик и подсказка.
- Можно добавить пассажира до общего лимита 10 человек.

## Оплата

После кнопки «Перейти к оплате» страница переключается на третий шаг без смены
URL, все три этапа прогресса становятся жёлтыми.

- Способы оплаты: СБП, карта банка РФ, цифровой рубль и карта иностранного
  банка.
- Для банковских карт показываются номер, срок действия, CVV и чекбокс
  сохранения карты.
- Промокод можно очистить и применить повторно; успешное применение показывает
  зелёное подтверждение.
- Платёжный запрос пока не отправляется: платёжный шлюз не подключён.

## Кнопка продолжения

Переиспользован общий `DbButton` варианта `primary`, размера `large`.

- Ширина заполняет внутреннюю часть карточки.
- Высота — `56px`.
- Горизонтальный padding — `20px`, вертикальный — `16px`.
- Текст — `20px / 24px`, medium.
- Жёлтый фон, тёмный текст, squircle-скругление Figma `16px`.
- Кнопка disabled, пока выбрано меньше трёх мест.
- После выбора трёх мест становится активной.
- Кнопка «Ввести данные пассажиров» переключает страницу на второй шаг.
- Кнопка «Перейти к оплате» доступна только при трёх отмеченных согласиях;
  она открывает третий шаг.
- На третьем шаге CTA меняется на «Оплатить».

## Общие компоненты

Повторно использованы `SiteHeader`, `SiteFooter`, `SegmentedControl`,
`DbButton`, `DottedLinkText`, `PageTransition`, `SiteLoader`, логотип и токены
дизайн-системы. Все новые скругления используют пару `rounded-db-* squircle`.

В светлой шапке кнопка профиля жёлтая, с иконкой человека в окружности.

## Проверка

```bash
cd frontend
bunx tsc --noEmit
bun run lint
BASE_URL=http://localhost:3002 node scripts/check-order.mjs
bun run build
```

`check-order.mjs` проверяет геометрию на ширинах `1920px` и `1710px`, отсутствие
overflow, карту мест, режимы переключателя, переходы между тремя шагами,
карточки пассажиров, способы оплаты, карточные поля, промокод, согласия, CTA и
жёлтую кнопку профиля.
